① Overview

Pikiz — Creative Agency Portfolio Template

Pikiz is a multi-demo Next.js 16 App Router theme for a creative / digital-marketing agency. It ships four distinct homepage designs (each with boxed, dark, RTL, and one-page variants), a full set of interior pages (about, services, work/portfolio, team, blog, pricing, contact, FAQ, login, 404), and a standalone marketing page used to sell the template itself.

Framework Next.js 16.3.8 (App Router) UI React 19 + React-Bootstrap Motion GSAP 3 + ScrollTrigger + SplitText Reveal wow.js + Animate.css Carousel react-slick Lang TypeScript, strict mode

Signal, not noise: the home pages/DemoLanding page contain marketing copy ("Elementor Page Builder", "20,000+ Clients") inherited from a sibling WordPress/HTML version of the theme — these are content strings, not actual features implemented in this Next.js codebase.

④ Routing #

Route path strings are centralized in src/data/routes.ts (ROUTES object) — internal links always go through ROUTES + SmartLink, never hard-coded href strings. Every page.tsx is a thin wrapper that sets metadata.title and renders one view, often with a prop that switches a variant.

⑧ Hooks #

Small reusable React hooks under src/hooks/.

useBodyClass.ts

Adds classes to document.body while mounted, removes on unmount/deps change (e.g. bg-peach, boxed-wrapper).

useGsapAnimations.ts

On route change, waits for preloader then calls initAnimations() inside requestAnimationFrame; disposes on cleanup.

useScrollPosition.ts

Tracks scrollY + upward scroll past 500px — drives the sticky cloned header reveal.

useStylesheet.ts

Mounts <link rel="stylesheet"> tags for component lifetime — swaps dark/RTL skins per variant.

useWow.ts

Dynamically imports wow.js, re-initializes ~50ms after each route change.

⑨ Animation system #

Motion is layered: wow.js (class-based scroll reveal via useWow) + GSAP / ScrollTrigger / SplitText (useGsapAnimations → initAnimations()), both re-initialized on every client-side route change and torn down to avoid leaks/duplicate triggers.

FileRole
gsap.tsRegisters plugins once (ScrollTrigger, ScrollToPlugin, SplitText); re-exports them; DOM helpers all/one/num/isRtl.
index.tsinitAnimations() — single orchestrator: text effects → per-home hero animations → generic section effects → interaction effects → pricing sticky-active logic. Returns one cleanup function that reverts GSAP context/matchMedia and runs all collected cleanups in reverse.
interactions.tscircleButtons() — magnetic hover + cursor-following dot (event-delegated for carousel clones); dualHoverText() — footer social-link roll-up via SplitText clones.
sections.tsBulk of scroll-triggered effects: per-home heroes, banner reveals, image parallax/clip-reveal/hover-reveal, service area/item reveals, pinned approach/brand-banner/FAQ-shape/funfact-shape/footer-CTA blocks, footer big-text, 404 entrance, pricing sticky-active.
text.tslettersFadeIn, splitTextScroll, titleOne (3D rotateX stagger), titleTwo (rise + de-blur), titleThree (per-letter stagger) — all keyed by CSS class.

⑫ Architecture notes #

Key takeaways worth keeping in mind before touching this codebase.

  1. Three-tier page pattern — app/.../page.tsx → src/views/... → src/components/sections/... → leaf components → src/data/*.ts. Follow this when adding a new page.
  2. Centralized routing — all cross-page navigation goes through the ROUTES constant and SmartLink; never hard-code internal href values.
  3. Layered animation — wow.js and GSAP/ScrollTrigger/SplitText both re-init on every client-side route change via useWow / useGsapAnimations, and both clean up afterward to avoid duplicate triggers or memory leaks.
  4. Variant switching via props, not duplication — dark/RTL/boxed/one-page/carousel variants are boolean or string props on view components (e.g. HomeTwo({ dark, rtl, onePage }), Packages({ carousel })); each home-* route is just a different prop combination into one of the four Home* views.
  5. Isolated landing sub-site — app/(landing)/ is a deliberately separate marketing/demo-chooser site (own CSS skin, own layout, no shared header/footer) distinct from the (site) pages it advertises.
